# 线索图与图片证据

## 选择叙事轴

先判断什么关系最能回答核心问题，再选主轴：

- **时间轴**：适合演变、调查、政策史、人物经历和事件复盘。
- **空间轴**：适合跨地区比较、迁移、地缘关系、供应链和现场报道。
- **事件链**：适合“发生了什么—各方如何反应—产生什么结果”。
- **因果链**：仅在证据能支持因果时使用；否则写成先后、相关或可能机制。
- **人物或机构关系**：适合权责、利益、合作和冲突结构。
- **问题—证据—结论**：适合解释性、科普和论证文章。

一篇文章只设一个主轴。辅助轴用于解释，不要让正文在多条结构之间来回跳。

## 节点契约

每个节点至少包含：

```yaml
id: N01
label: 节点标题
axis_value: 具体日期、地点、事件或关系位置
claim_ids: [C01, C02]
source_ids: [S01, S02]
media_ids: [M01]
role: opening | context | turn | evidence | consequence | ending
uncertainty: 无，或明确说明尚未解决的冲突
```

节点不能只有概括句而没有事实编号。一个节点包含太多互不相干的事实时，应拆分。

## 边契约

边必须使用明确类型：

- `before` 或 `after`：时间先后；
- `located_in` 或 `moves_to`：空间关系；
- `responds_to`：回应；
- `enables` 或 `constrains`：促成或限制；
- `contradicts`：证据冲突；
- `supports`：论据支持；
- `causes`：只有充分证据支持时使用。

不要把相关性写成因果。若只能确认同时发生，使用 `coincides_with` 并在说明中限定。

## 图片分级

按证据价值排序：

1. 原始文件、官方图表、原始数据可视化、档案页；
2. 可定位时间地点且有来源的现场照片；
3. 有明确作者、机构、许可和上下文的媒体图片；
4. 获得许可的资料图；
5. 模型生成示意图或装饰图。

对每张图记录：来源 URL 或本地路径、作者或机构、发布日期、许可或合理使用说明、对应节点、图注、替代文本、裁切或编辑记录。

### 事实图片规则

- 用来证明人物在场、文件内容、现场状态、数值或地点的图片必须来自真实来源。
- 截图要保留能定位原文的标题、日期或页码；正文仍需文字引用，图片不是引用替代品。
- 同一来源的缩略图失效时，优先回到原页获取，不要用“相似图片”顶替。
- 图表重绘必须保留数据来源、口径和单位，并标明“据某数据重绘”。

### 生成图规则

只有以下情况才允许生成：抽象概念、无具体事实责任的开场氛围、流程示意或不对应真实人物或现场的装饰插画。必须同时满足：

- `origin: generated`；
- `supports_fact: false`；
- 不绑定 `claim_ids`；
- 图注包含“模型生成示意图”；
- 不模仿新闻现场、真实文件、官方图表或特定人物肖像来制造真实性。

## `clue-graph.md` 建议结构

```markdown
# 主叙事轴与选择理由
## Mermaid 线索图
## 节点明细
## 边明细
## 节点—事实—来源—图片矩阵
## 缺失图片与处理决定
## 不确定性
```

Mermaid 只用于浏览结构；机器验收所需的节点、边和媒体关系仍写入 `run.json`。
